# 신고 접수와 중단 절차

권리자나 그 대리인이 이 프로젝트에 대해 문제를 제기하면, **논쟁하기 전에
먼저 멈춘다.** 이 문서는 그 순서를 미리 정해 둔 것이다. 상황이 생긴 뒤에
정하면 늦고, 그 사이에 배포가 계속된다.

> ⚠️ 이 절차는 **법적 대응 방침이 아니다.** 기술적으로 무엇을 어떤 순서로
> 하는지만 적는다. 법적 판단은 별도이고 이 문서가 대신하지 않는다.

---

## 1. 연락 채널

| 무엇 | 어디 |
|---|---|
| 권리자·대리인 문의 | 배포 페이지의 연락처 · 리포의 이슈 |
| 보안·개인정보 | 같은 곳 |

⚠️ **아직 공개 배포를 안 했으므로 채널이 확정되지 않았다.** 첫 배포 전에
여기를 실제 주소로 채우고, 배포 페이지와 `README`에서 같은 곳을 가리키게
한다. 그 전에는 공개하지 않는다 — 연락할 데가 없는 배포는 이 절차 전체를
무의미하게 만든다.

접수 시 남길 것 (요청자에게 요구하지 않는다. 우리가 기록한다):

- 받은 날짜와 시각
- 무엇에 대한 것인가 (이름 · 그림 · 코드 · 데이터 · 전체)
- 요청 내용 (수정 · 중단 · 삭제)

## 2. 즉시 중단 (30분 안)

**판단하기 전에 먼저 내린다.** 검토는 내려놓고 한다.

```sh
# ① 호스팅을 끈다. 가장 확실한 것은 배포 자체를 없애는 것이다
#    (플랫폼마다 다르다 — 첫 배포 때 이 자리에 실제 명령을 적는다)

# ② 그동안 아무 데도 안 열리게 한다
#    정적 호스팅이면 index.html 하나만 남기고 전부 뺀다
```

앱 셸만 내려도 **사용자의 OPFS 설치본은 그대로 남는다.** 그건 그 사람의
기기 안에 있고 우리가 지울 수도, 지울 이유도 없다. 다만 앱이 안 열리므로
접근할 수는 없다 — 리포트는 `.rpsave`로 이미 손에 있다 (IMPORT.md §11).

Service worker가 캐시한 앱 셸 때문에 **이미 방문한 사람에게는 한동안 열린다.**
그것까지 끊으려면 셸을 내리기 전에 SW를 무효화하는 배포를 한 번 해야 한다:

```sh
# sw.js를 "자기 자신을 등록 해제하는" 내용으로 한 번 배포하고, 그 다음에 내린다
```

## 3. 접수 뒤 순서

| 언제 | 무엇 |
|---|---|
| 30분 안 | 배포 중단 (§2) |
| 당일 | 접수 확인 회신. 무엇을 이미 중단했는지 적는다 |
| 1일 안 | 무엇이 문제인지 특정한다 — 이름 · 그림 · 데이터 · 코드 중 어느 것인가 |
| 그 뒤 | 아래 §4의 갈래대로 |

**되돌리는 배포를 먼저 하지 않는다.** 문제를 특정하기 전에 "이것만 고쳤다"고
다시 올리면 두 번째 요청을 받는다.

---

## 4. 무엇이 문제인가에 따라

| 문제 | 할 수 있는 것 | 못 하는 것 |
|---|---|---|
| 앱 셸의 그림·워드마크 | 갈아 끼운다. `shellArt.mjs`가 무엇을 그렸는지 이미 적어 둔다 | — |
| 프로젝트 이름 | 이름을 바꾼다. 코드에는 `APP_ROOT`·manifest·`<title>` 세 곳이다 | 이름의 상표 위험을 코드로 없앨 수는 없다 |
| 번들 안 제3자 게임 데이터 | 지금도 blocker다 (DEPLOY.md §4) | — |
| Git 히스토리의 원본 유래 블롭 | `docs/HISTORY.md`의 절차 | 남이 이미 클론했으면 못 지운다 |
| 게임 구조·세계관·2차적 저작물 | **코드로 해결되지 않는다** | 이 자리는 법률 검토와 권리자의 판단이 필요하다 |

---

## 5. 다시 올리기

**기본은 "안 올린다"다.** 다시 올리려면 셋이 다 있어야 한다:

1. 무엇이 문제였는지 특정됐고
2. 그것이 기술적으로 제거됐고 `pnpm release:check`가 그 사실을 **재서** 통과하고
3. 권리자 쪽과의 연락이 끝났다

셋 중 하나라도 비면 안 올린다. "고친 것 같다"로 다시 올리는 것이 가장 나쁜
선택이다 — 첫 번째 요청보다 두 번째가 훨씬 세다.

---

## 6. 미리 해 둘 것

이 절차가 실제로 도는지는 **써 보기 전에는 모른다.** 첫 배포 전에:

- [ ] 연락처를 실제 주소로 채운다 (§1)
- [ ] 배포 중단 명령을 그 플랫폼의 실제 명령으로 적는다 (§2)
- [ ] SW 무효화 배포를 한 번 리허설한다 — 그게 안 되면 캐시된 셸이 계속 열린다
- [ ] 배포 페이지에서 이 문서로 가는 링크를 건다
