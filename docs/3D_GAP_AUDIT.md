### 현재 완료 판정

현재 게임에 연결되어 플레이 가능한 기능 중, 감사 기준상 **순수 2D 판때기·정적 상태·무연출로
남은 3D 공백은 없다.** 원본 GLB가 없는 캐릭터/소품은 절차형 3D 폴백을 사용하고, 텍스트·메뉴·
배틀 HP바는 설계상 DOM 예외다. 아직 게임 로직 자체가 범위 밖인 콘테스트·지하통로·통신 기능은
“3D화 완료”에 포함하지 않으며, 기능을 구현할 때 별도의 3D 무대가 필요하다.

## 1. 결론

Radiant Platinum의 3D 기반은 이미 성립한다. 영속 WebGPU/R3F Canvas, 270개 맵의 원작 지오메트리, 절차적 나무·풀·꽃·바위·물, 포켓몬 493종과 폼 64개의 3D 모델, 배틀 무대 30종, 플레이어·자전거·일부 NPC 모델이 실제 런타임에 연결되어 있다.

그러나 “플래티넘 3D 리메이크”라는 기준으로 보면 다음 여섯 영역이 아직 2D, 정적, 범용 대체 연출 또는 무연출이다.

1. **캐릭터 범위** — 플레이어는 여주인공 모델 하나로 고정되고, NPC 배치의 78.1%는 2D 판때기다.
2. **필드 행동** — 낚시, 파도타기, 비전기술 컷인, 공중날기 같은 행동은 규칙만 있고 3D 몸·도구·탈것 연출이 없다.
3. **환경 동작** — 날씨, 문, 관절 소품, 엘리베이터·승강판·체육관 장치가 정적이거나 소리·대기시간만 있다.
4. **배틀 연출** — 포켓몬과 무대는 3D지만 471개 기술을 5개 범용 도형으로 표시하고, 트레이너·몬스터볼·포획·날씨·상태이상 시각 연출이 없다.
5. **전용 장면** — 인트로, 진화, 부화, 명예의 전당, 일부 전설 조우는 DOM/CSS와 도트 이미지 중심이다.
6. **공간 정합성** — 턱 720칸이 평면이고, 다리 아래 통과와 깨어진 세계의 표면 방향에 맞춘 몸·카메라 회전이 없다.

가장 먼저 고쳐야 할 것은 **플레이어 성별 모델, NPC 3D 비율, 필드 행동 연출, 배틀 VFX**다. 이 네 가지는 정상 플레이 내내 반복해서 보이며 3D와 2D가 한 화면에서 직접 충돌한다.

## 2. 판정 기준

| 판정 | 뜻 |
|---|---|
| 3D 완료 | 메시·머티리얼·조명·카메라·필요 동작이 3D 씬에서 실제로 돈다. |
| 부분 3D | 3D 메시가 있지만 대상 범위, 동작, 외형 변형 또는 전용 연출이 빠졌다. |
| 2.5D 대체 | 평면 스프라이트, 실루엣 압출, 범용 도형 등으로 깊이만 보완했다. |
| 3D 미구현 | DOM/CSS/PNG만 쓰거나, 상태와 소리만 있고 3D 표현 객체가 없다. |
| 의도적 2D | 설계상 DOM이어야 하는 메뉴·텍스트·HUD. 결함으로 세지 않는다. |

`docs/PLAN.md:277-287`은 메뉴·대화·배틀 HUD를 DOM으로, 이름표·데미지 팝업·상호작용 프롬프트를 3D로 정한다. 따라서 모든 `<img>`나 DOM을 무조건 결함으로 분류하지 않았다.

1. 원작 기술 연출 표를 추출해 기술 → 시퀀스/타이밍/사운드 이벤트를 데이터화한다.
2. 471개를 일일이 하드코딩하지 말고 방출체, 궤적, 충돌, 지속장, 화면 효과, 카메라 큐의 조합 그래프로 만든다.
3. 포켓몬 모델 로더에 `mouth/hand/center/feet` 앵커를 추가한다.
4. 더블 배틀의 단일·인접·전체 타깃을 실제 여러 월드 좌표로 전달한다.

### 7.2 트레이너와 몬스터볼 연출이 없음 — P1

`src/scene/battle/BattleStage.tsx:581-620`의 배틀 장면 구성은 무대, 포켓몬 네 자리, 기술 VFX뿐이다. 트레이너 모델이나 몬스터볼 객체가 없다. `src/ui/battle/BattleSound.tsx:49-50`은 투척·등장 효과음만 재생한다.

빠진 것:

- 트레이너 등장, 표정, 지시, 몬스터볼 투척.
- 교체 시 회수 빔/볼과 새 포켓몬 등장.
- 포획 볼 궤적, 흔들림, 성공/탈출.
- 도망/패배/승리 시 캐릭터 반응.

현재 추출한 NPC/트레이너 모델과 포켓몬 모델을 재사용할 수 있으므로 신규 모델 수보다 장면 오케스트레이션이 핵심이다.

### 7.3 이로치·성별·전투 중 폼 변화가 3D 외형에 반영되지 않음 — P1

근거:

- 배틀 뷰는 `shiny`와 `gender`를 보유한다(`src/engine/battle/view.ts:31-39`).
- `BattleStage`의 `Slot`은 `species`, `form`, `mine`만 모델 로더에 넘긴다(`src/scene/battle/BattleStage.tsx:191-223`).
- `loadMonModel`의 선택 키도 종과 폼뿐이다(`src/scene/battle/monModel.ts:90-106`).
- 저장/요약 화면은 이로치를 판정하지만 3D 장면에서는 `shiny` 사용처가 없다.
- `docs/PARITY.md:159`은 캐스퐁·체리버처럼 배틀 안에서 바뀌는 폼을 화면이 따라가지 못한다고 명시한다.

결과:

- 이로치 개체도 보통색 3D 재질로 나온다.
- 성별 외형 차이가 있는 종도 기본 외형만 나온다.
- 전투 규칙상 폼/타입은 바뀌어도 보이는 모델은 이전 상태로 남을 수 있다.
- 폼 모델은 64개가 실제로 있으므로 “자산 없음”보다 상태 전달·재질 선택 문제다.

### 7.4 배틀 날씨·상태·필드 효과가 텍스트뿐 — P1

- 배틀 뷰는 `weather`를 저장한다(`src/engine/battle/view.ts:62`, `244-245`).
- `BattleStage`는 이 값을 읽어 비·눈·모래바람 등을 렌더하지 않는다.
- 상태이상은 DOM HUD 태그와 메시지로만 표시한다(`src/ui/battle/BattleScreen.tsx:466-471`).

빠진 시각층: 날씨 파티클, 독/화상/마비/얼음/잠듦, 스텔스록·압정·빛의장막·리플렉터·트릭룸·중력·순풍 같은 지속 효과.

### 7.5 런타임 폴백은 존재하지만 완성 3D로 세면 안 됨

- 모델이 없으면 80×80 도트 평면으로 폴백한다(`BattleStage.tsx:213-240`).
- 모델과 도트를 둘 다 못 받으면 단색 도형으로 폴백한다(`BattleStage.tsx:242`, `423-439`).
- 배틀 무대 로딩 중에는 평면 지면이 선다(`BattleStage.tsx:581-585`).

이는 실패 복구로는 적절하지만 캡처·QA에서는 폴백 발동률을 별도로 기록해야 한다. “배틀이 보인다”와 “3D 자산이 정상 로드됐다”를 같은 성공으로 처리하면 누락을 놓친다.

## 8. 전용 장면의 3D 공백

### 8.1 새 게임 인트로 — P1

현재 `IntroScreen`은 거의 전부 DOM이다.

- `src/ui/intro/intro.css.ts:3-4` — 마박사 그림 자리를 비워 두고 추후 초상을 얹도록 되어 있다.
- `intro.css.ts:24-31` — 현재 그림 자리에는 몬스터볼만 선다.
- `intro.css.ts:33-55` — 몬스터볼도 3D 모델이 아니라 CSS 원과 그라디언트다.
- `intro.css.ts:49-51` — 열린 뒤 나와야 할 이어롭이 없고 빛만 남는다고 적혀 있다.
- 주인공/라이벌 성별과 이름 선택에도 3D 인물 미리보기가 없다.

필요 장면: 마박사 모델/초상, 몬스터볼 모델, 이어롭 등장, 남/여 주인공과 라이벌 확인, 카메라·조명 전환.

### 8.2 파트너 선택 — 부분 3D, P1

- 가방·볼·바닥판은 `StarterStage`에서 3D로 돈다.
- 가방 여는 JNT0 곡선은 없고 41프레임 뒤 닫힌/열린 메시를 교체한다.
- 선택 확인 창의 스타팅 포켓몬은 `src/ui/field/ChooseStarter.tsx:80,233`에서 도트 배경 이미지다.

완료 기준은 가방 뚜껑의 실제 연속 애니메이션, 볼 반응, 선택 포켓몬의 3D 등장/대기다.

### 8.3 진화 — 2D, P1

`src/ui/menu/EvolutionScreen.tsx:197-228`은 앞모습 PNG를 `<img>`로 표시하고 DOM/CSS로 전환한다. 진화 규칙과 취소는 완성되어도, 3D 모델 교차 페이드·실루엣·파티클·카메라는 없다.

### 8.4 알 부화 — 2D, P1

`src/ui/menu/HatchScreen.tsx:89-108`은 알/포켓몬 PNG를 `<img>`로 표시한다. 흔들림·깨짐 시간은 있지만 3D 알 메시, 금, 파편, 빛, 부화 포켓몬 모델 등장은 없다.

### 8.5 명예의 전당 — 기능은 연결됐지만 2D, P1

- 현재 작업 트리의 `src/ui/menu/MenuLayer.tsx:21-22,74-75`는 전당 등록 화면과 PC 재생 화면을 실제 메뉴 계층에 마운트한다.

- `src/ui/field/PokemonPreview.tsx:13-20`은 전설 조우 전 모습을 도트 `<img>` 창으로 띄운다.

전설은 일반 야생 배틀 모델을 재사용하되, 월드 배치·등장 애니메이션·환경 반응·카메라 시퀀스를 별도 구현해야 한다.

### 8.7 타이틀 — 의도적인 2D 예외, P2

`src/ui/screens/titleScreen.css.ts:29-59`은 three.js를 싣지 않기 위해 2.3MB 정적 PNG와 CSS 그라디언트를 사용한다. 이는 초기 청크 ≤150KB 목표를 위한 명시적 선택이다.

따라서 즉시 결함으로 보지는 않는다. 다만 “모든 주요 장면 3D”가 제품 목표라면 다음 중 하나를 결정해야 한다.

- 현재 정적 타이틀을 공식 예외로 문서화한다.
- 첫 상호작용 뒤 지연 로드되는 가벼운 3D 타이틀로 교체한다.
- 배경은 정적 유지하고 안개·빛·입자만 셰이더/Canvas로 보강한다.

## 9. 월드 좌표 3D UI 공백 — P2

`docs/PLAN.md:277-285`은 다음을 3D Sprite/Html로 정한다.

- 이름표.
- 데미지 팝업.
- 상호작용 프롬프트.

현재 `src/scene`과 `src/ui`에는 이 세 계층의 구현을 찾지 못했다. 배틀 피해는 HP바와 메시지로만, 필드 상호작용은 별도 월드 프롬프트 없이 입력으로만 처리된다.

또한 화면 전환은 계획상 셰이더지만 실제 `src/ui/field/FadeOverlay.tsx`는 DOM 색 오버레이다. 접근성·텍스트·메뉴는 DOM이 맞지만, 장면 공간에 붙어야 하는 피드백과 전체 화면 장면 전환은 계획대로 3D/포스트프로세스 계층에 두는 편이 일관적이다.

## 10. 2.5D 또는 리메이크 품질 부채

아래는 기술적으로 3D이므로 “미구현”으로 세지 않았지만, 새 3D 아트로 완전히 리메이크된 상태도 아니다.

### 10.1 원작 DS 청크·소품 지오메트리 재사용

`ChunkModels`는 원작 NSBMD 지오메트리를 실제 3D로 렌더한다. 하지만 `docs/PLAN.md:515`의 원래 원칙은 이를 최종 렌더가 아니라 블록아웃 기준으로 쓰는 것이었다. 현재 코드는 품질을 다음 방식으로 보완한다.

- 나무·풀·꽃·바위는 절차적 3D로 교체.
- 울타리·표지판은 원작 실루엣을 한 텍셀 두께로 압출.
- 빠진 소품 면은 원작 색으로 메움.
- 원작 텍스처와 저해상도 형태는 유지.

즉 **공간은 3D지만 아트는 DS 원본 기반 2.5D 리마스터**다. 신규 모델링을 할지 현재 데이터 보존형 스타일을 최종 방향으로 승인할지 ADR이 필요하다.

### 10.2 절차적 자연물은 원작 형상이 아니라 새 형상

나무·풀·꽃·바위는 3D화 완료지만 원작에는 입체 기준이 없어서 형상 자체는 프로젝트가 만든 것이다. 자리·크기·색은 원작 데이터에서 오지만 실루엣은 새 해석이다. 향후 BDSP 환경 모델로 교체하면 현재 충돌·가림·성능 기준이 바뀌므로, “현재 절차적 형상이 최종 아트인가”를 먼저 결정해야 한다.

## 11. 의도적 2D — 3D 공백으로 세지 않을 것

다음은 현재 아키텍처상 DOM/2D가 맞다.

- 시작 메뉴, 설정, 도감, 가방, 파티, 박스, 세이브.
- 대화창, 선택지, 이름 입력.
- 배틀 HP바, 기술/도구/교체 선택, 상태 태그.
- 타운맵, 포켓치, 모험노트, 트레이너카드 같은 인게임 장치 화면.
- 아이템 아이콘, 도감/요약의 정보용 포켓몬 그림.

이 화면들을 3D로 바꾸는 것은 3D 리메이크 완성도가 아니라 텍스트 품질·접근성·입력·성능을 악화시킬 가능성이 크다. 다만 진화·부화처럼 **화면 자체가 연출인 경우**와 파트너 선택·전설 미리보기처럼 **3D 씬과 직접 이어지는 경우**는 예외로 위에 분리했다.

## 12. 구현 순서 제안

### 1단계 — 한 화면의 혼합 스타일 제거

1. 남주인공 모델 선택을 연결한다.
2. NPC 미매칭 목록을 사람/이벤트 오브젝트로 분리하고 사람의 3D 커버리지를 올린다.
3. 이로치·성별·전투 중 폼을 배틀 모델 선택에 전달한다.
4. NPC 모델/스프라이트 혼합률을 맵별로 자동 리포트한다.

완료 게이트:

- 성별별 새 게임 캡처에서 올바른 플레이어가 보인다.
- 주요 이야기 맵의 가시 인물 중 판때기 0개.
- 이로치·성별 차이·캐스퐁/체리버 폼 전환 시 모델/재질이 갱신된다.

### 2단계 — 반복 필드 행동 3D화

1. 공통 `FieldActionStage`/`ActionRig` 계약을 만든다.
2. 낚시 → 파도타기 → 비전기술 → 공중날기 순으로 구현한다.
3. 행동마다 몸 클립, 부착 모델, 월드 FX, 소리 이벤트를 데이터로 묶는다.

완료 게이트:

- 상태만 바뀌고 화면이 그대로인 필드 기술 0개.
- 1인칭·3인칭 모두 부착점과 카메라가 깨지지 않는다.

### 3단계 — 배틀 표현 계층 완성

1. 기술 연출 데이터 추출.
2. 조합형 VFX 그래프와 포켓몬 앵커.
3. 트레이너·볼·포획/교체.
4. 날씨·상태·지속 필드 효과.

완료 게이트:

- 471개 기술 전부가 최소 하나의 유효한 데이터 시퀀스를 가진다.
- 기술별 길이, 타격 프레임, 카메라, 사운드가 같은 타임라인을 본다.
- 더블 배틀의 전체/인접/단일 대상 캡처가 구분된다.

### 4단계 — 환경과 전용 장면

1. 문 NSBCA/JNT0과 장치 애니메이션.
2. 필드·배틀 날씨.
3. 턱·다리·접지 보정.
4. 인트로·진화·부화·전설·명예의 전당.
5. 깨어진 세계 표면 프레임과 카메라 roll.

- 배틀 모델 선택 키에 `species/form/gender/shiny` 조합 테스트.
- 471개 기술의 VFX 시퀀스 존재·길이·타격 이벤트 테스트.
- 문·장치 애니메이션의 클립 존재와 끝 프레임 테스트.
- 720개 턱의 양쪽 높이 차와 도약 착지점 테스트.

### 시각 회귀 캡처

최소 캡처 세트:

1. 남/여 주인공, 걷기·달리기·자전거·파도타기.
2. 3D NPC와 폴백 NPC가 가장 많이 섞이는 맵.
3. 낮/밤/비/눈/모래바람.
4. 문, 엘리베이터, 승강판, 체육관 기믹.
5. 싱글/더블 배틀, 이로치, 성별 차이, 폼 전환.
6. 물리/특수/상태/전체/다중 타격/날씨 기술.
7. 인트로, 파트너 선택, 진화, 부화, 명예의 전당.
8. 턱, 다리 위·아래, 부유 의심 건물, 깨어진 세계 벽 걷기.

### 성능 게이트

3D 커버리지를 올리면서 기존 예산을 같이 지켜야 한다.

- 1080p 60fps 목표.
- High 드로우콜 ≤300.
- NPC 3D 상한을 늘릴 때 CPU 스키닝과 VRAM을 별도 측정.
- 기술 VFX는 객체 풀을 사용하고 매 프레임 React 상태 갱신을 금지.
- 타이틀 3D화 여부는 초기 청크 ≤150KB와 별도 트레이드오프로 판단.

## 14. 감사 메모와 문서 불일치

- `docs/PLAN.md:2905-2907`의 “폼은 첫 판만 쓴다”는 설명은 현재 코드/자산과 맞지 않는다. 현재 `public/models/pokemon/index.json`은 기본 493 + 폼 64 = 557개이며 `loadMonModel(species, form)`이 폼 키를 우선한다.
- 다만 `src/scene/battle/BattleStage.tsx:301-305`는 모션 타이밍 조회에 여전히 폼 0을 넘긴다. **모델 폼은 구현됐지만 폼별 타격 타이밍은 미완성**이다.
- `docs/PLAN.md`의 NPC 주석 일부는 760/21.4%, 정본과 테스트는 777/21.9%다. 이 문서는 현재 테스트 수치 777/3,555를 따른다.
- 작업 트리에는 명예의 전당 관련 미커밋 작업이 진행 중이다. 감사 도중 `HallOfFameScreen`과 `PCHallOfFameScreen`이 메뉴·서비스에 연결된 최신 상태를 다시 확인해 §8.5에 반영했으며, 해당 구현 파일 자체는 수정하지 않았다.
- `.audit/probe/mapAudit.mjs`는 실행 중인 Vite 서버를 요구한다. 이번 감사에서는 소스와 기존 전수 측정(`PLAN.md:3222-3232`)을 대조했으며, 문서에 기록된 720턱/106접지 의심 수를 그대로 사용했다.
