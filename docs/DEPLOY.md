# 배포

공개 서버에 무엇을 올리고, 올리기 전에 무엇을 통과해야 하는지.

기술적인 무전송·무배포 경계를 지키는 것이 이 문서의 범위다. **그것이 법적
면책을 뜻하지 않는다** — 남는 위험은 COPYRIGHT.md §3에 있다.

## 1. 지금은 못 올린다

미해결 release blocker가 있다. `pnpm release:check`가 실패한다.

정본은 [`tools/distribution/blockers.mjs`](../tools/distribution/blockers.mjs)고
**손으로 관리하는 목록이 아니다** — 하나하나가 `resolved()`로 직접 재고, 재서
풀렸으면 스스로 빠진다. 손으로 지우는 목록은 일이 끝나서가 아니라 잊혀서 비워진다.

| # | blocker | 지금 (2026-08-10) | 어디 |
|---|---|---|---|
| 1 | 번들에 제3자 정적 게임 데이터 | ✅ **0개 모듈 · 0바이트** (8.9MB에서) | §4 |
| 2 | 앱 셸 그림이 공식처럼 보인다 | ✅ 추상 표식으로 바꿨다 (워드마크 0 · 캐릭터 0) | COPYRIGHT.md §11 |
| 3 | CSP 응답 헤더를 실제 호스트에서 잰 적이 없다 | ⛔ 호스트 미정 | §3 |
| 4 | BDSP 변환이 없어 3D 에셋을 만들 수 없다 | ✅ 막힌 자리 0곳. 무대 g001이 개발 추출기와 **모두 같다** | IMPORT.md §12 |
| 5 | 필수 설치 그룹이 다 구현되지 않았다 | ✅ **23/23** — Platinum 열아홉 · BDSP 넷 | IMPORT.md §8 |
| 6 | 브라우저 실측이 통과 상태가 아니다 | ⛔ BLOCKED 2건 | §5 |
| 7 | 배포물이 어느 커밋에서 나왔는지 말할 수 없다 | 깨끗한 나무에서 빌드하면 ✅ | §2 |
| 8 | 원본 유래 산출물이 Git 히스토리에 남아 있다 | ⛔ 커밋 46개 · 17.8MB | HISTORY.md |

⑦은 조건부다 — 깨끗한 나무에서 빌드하면 스스로 빠지고, 커밋 안 한 변경이
섞이거나 CI 밖에서 빌드하면 다시 선다. 그것이 자기가 재는 blocker의 모양이다.

④와 ⑤는 이번에 함께 풀렸다. 필수 스물셋이 전부 브라우저 변환기를 갖고,
**산출물이 개발 추출기와 바이트로 같다**(그림만 픽셀로 잰다 — deflate가 같은
픽셀에서 여러 정답을 내기 때문이다). BDSP 쪽은 무대 g001이 메시 158개·정점
141,918개·픽셀 1,196,032개까지 **모두 같고**, 인물과 포켓몬은 그림만 최대
2~3/255 다르다(임자는 32비트 `powf` 하나다 — `tools/spike/glbDiff.py`).

②는 이번에 풀렸다. 아래에 왜 그것이 **새로 생긴 것이 아니라 새로 보이게 된 것**
이었는지 남긴다 — 같은 함정을 다시 밟지 않으려는 것이다.

②는 바이트 검사로는 절대 못 잡는 자리였다 — 셸 그림 셋은 전부 우리가 만든
PNG라 출처 검사도 매직바이트 검사도 히스토리 감사도 다 통과한다. 화면을 열어
보고서야(`node tools/shot/title.mjs`) 타이틀 배경에 금속 질감의 `POKEMON`
워드마크가 그려져 있는 것이 보였다. 원본 바이트를 안 싣는 것과 공식처럼 보이지
않는 것은 다른 문제고, BYOR는 앞만 줄여 준다.

⑤는 전에 ④ 안에 섞여 있었다. Platinum 쪽 7개가 안 옮겨진 것은 BDSP와 무관한
별개의 미완인데, 하나로 두면 BDSP를 푸는 날 조용히 함께 풀린다.

blocker와 **위반**은 다르다. 위반은 지금 고칠 수 있는 것이라 `pnpm build`를
세운다. blocker는 아직 못 고친 것이라 빌드는 통과시키고 매번 숫자를 찍되,
`--release`에서 실패로 바꾼다. 개발이 멈추지 않으면서 공개는 막힌다.

## 2. 무엇이 올라가는가

`dist/`뿐이다. 그 안에 들어가는 것은 두 갈래고 각각 따로 심사한다.

| 갈래 | 무엇 | 심사 |
|---|---|---|
| 복사 | `public/`의 앱 셸 5개 | `appShell.mjs` 파일 단위 allowlist · docs/APP_SHELL.md |
| 컴파일 | `src/` + `node_modules/` → `assets/*.js` | `pnpm provenance` (§4) |

`public/data`(64MB)와 `public/models`(581MB)는 개발 기계에 그대로 있고
`dist/`에 **안 들어간다** — `copyPublicDir: false`이고 셸 목록에 없다.
빌드 뒤 `boundary:post`가 실제 `dist/`를 다시 훑어 그것을 확인한다.

⚠️ **`pnpm dev`는 배포 수단이 아니다.** 개발 서버는 `public/` 전체를 준다 —
645MB를 포함해서다. 공개 주소에 띄우면 안 된다. `vite preview`도 CSP 응답
헤더가 없으므로 공개 배포로 쓰지 않는다.

### `src/` 안의 자료 표

경로 규칙은 이것들을 하나도 못 봤다. `src/**/*.json`은 `public/data` 검사에
안 걸리고 이름도 `.json`이라 `dist` 규칙도 통과한다. 그런데 그 안에 롬에서
읽은 값이 있을 수 있다 — 실제로 있었다.

정본은 [`tools/distribution/dataTables.mjs`](../tools/distribution/dataTables.mjs)이고
**목록에 없으면 빌드가 선다.** `inBundle: false`는 주장이 아니라 검사 대상이다:
빌드 뒤에 표식 문자열을 `dist/`에서 실제로 찾아본다.

| 표 | 무엇 | 배포물에 |
|---|---|---|
| `src/import/platinum/supported.json` | 지역판 지문 · ARM9 표 자리와 개수 | 들어간다 (§2 메타데이터) |

`src/data/textBanks.json`은 **지웠다.** 뱅크 724개의 이름·상수와 함께 롬 뱅크
헤더 +2에서 읽은 **암호화 키(u16)** 와 로케일별 엔트리 수를 들고 있었다 —
자리나 개수가 아니라 롬에서 읽은 값이다 (COPYRIGHT.md §6).

지금은 `src/import/platinum/textBanks.ts`가 **이름 순서에서 자리를 계산**한다.
남은 것은 셋 다 이름이다: 뱅크 순서 · CJK에 없는 뱅크 · 끼워 넣는 자리.
계산이 맞는지는 사용자의 롬이 답한다 — `readBankLayout`이 narc의 실제 뱅크 수와
(키, 엔트리) 쌍의 유일성을 그 자리에서 확인하고 어긋나면 던진다.

### 경로가 아니라 내용으로 훑는다

⚠️ **위 검사는 전부 우리가 기억하는 경로만 본다.** 이름을 바꿔 옮겨 놓으면
조용히 통과한다. 그래서 `boundary:pre`가 **tracked 파일 전부**를, `boundary:post`가
**배포물 전부**를 열어 머리 바이트(NARC·SDAT·NCLR·NCGR·NSBMD·NSBTX·UnityFS)와
지운 값의 모양을 직접 본다. 실측: tracked 493개 · 배포물 30개 — 원본 유래 0개.

### 이 배포물이 어디서 나왔는가

빌드가 `.audit/build.json`에 판과 신원을 적는다.

| | |
|---|---|
| `version` | `package.json`의 SemVer. **비교해도 되는 것은 이것뿐이다** |
| `buildId` | `dev` · `a1b2c3d` · `a1b2c3d-dirty` |

⚠️ **한 문자열로 두지 않는다.** SemVer에서 `+` 뒤는 빌드 메타데이터라
우선순위를 안 바꾼다 — `0.1.0+dev`와 `0.1.0+a1b2c3d`는 SemVer상 같은 판이다.
호환 판정에 그 문자열을 쓰면 "다르게 생겼으니 다른 판"으로 잘못 읽는다.
봉투에 적히는 `0.1.0+a1b2c3d`는 사람이 버그를 재현할 때 쓰는 표시다.

`-dirty`와 `dev`는 릴리스에서 막는다 (blocker 4). 커밋 안 한 나무에서 나온
배포물은 **재현이 안 된다** — 해시가 가리키는 소스가 실제로 돌아간 소스가 아니다.

### 첫 화면 예산

`boundary:post`가 `dist/index.html`이 적어 둔 것(진입 스크립트 ·
modulepreload · 스타일시트)을 gzip해서 잰다. 목록을 손으로 안 적는 이유는
코드 쪼개기가 바뀔 때마다 갈라지기 때문이다.

| | gzip |
|---|---:|
| 예산 (PLAN §10.4) — 넘으면 빌드가 선다 | 150.0kB |
| 내부 목표 — 넘으면 경고 | 135.0kB |
| 실측 (2026-08-11) | **120.7kB** |

목표를 예산보다 낮게 둔 것은 "통과했다"와 "간신히 통과했다"를 가르기 위해서다.
한동안 목표를 넘고 있었는데(140.3kB), **화면에 안 그려지는 것 둘이 초기 그래프에
들어와 있던 것**이 임자였다:

| 무엇 | 왜 들어와 있었나 | gzip |
|---|---|---:|
| 배틀 UI 서른 모듈 | `App`이 `<BattleScreen />`을 늘 그렸다. 안에서 `phase === 'off'`면 null을 내니 화면에는 아무 표시가 없었다 | −18.0kB |
| 소리 뭉치 | 타이틀의 커서 소리(`useMenuKeys`)와 `BattleSound`가 `music`을 정적으로 잡았다. 소리는 사용자가 한 번 건드리기 전에는 어차피 안 난다 | −1.6kB |

둘 다 **크기가 아니라 배선 문제였다.** 예산 검사는 총합만 보므로 이런 것을 못
가른다 — 이제 `app/initialChunk.test.ts`가 모듈 그래프를 직접 걸어서 둘 다
막는다.

## 3. CSP — 응답 헤더가 필수다

정본은 [`tools/distribution/csp.mjs`](../tools/distribution/csp.mjs)의 `CSP`다.

```
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:;
media-src 'self' blob:;
connect-src 'self' blob:;
worker-src 'self';
font-src 'self';
manifest-src 'self';
frame-src 'none';
object-src 'none';
base-uri 'none';
form-action 'none';
frame-ancestors 'none'
```

`connect-src 'self' blob:`가 무전송 경계다 — 바깥 오리진이 없으니 사용자가
고른 롬 바이트가 나갈 곳이 없다.

### meta로 대신할 수 없다

빌드가 `<meta http-equiv="Content-Security-Policy">`도 넣지만 **그것으로 CSP가
있다고 세지 않는다.** 셋이 다르다:

- `frame-ancestors`는 meta에서 **무시된다.** 클릭재킹을 막는 것은 헤더뿐이다
- meta는 그 태그를 파싱하기 **전에** 시작된 요청을 못 막는다
- meta는 `report-uri`/`report-to`를 못 쓴다

meta를 넣는 이유는 헤더가 잘못 설정된 채 올라갔을 때 아무 방어도 없는 것보다는
낫기 때문이지, 헤더를 대신하기 때문이 아니다.

### 안 넣는 것

- `wasm-unsafe-eval` — BDSP 변환에 WASM이 실제로 필요하다고 증명되기 전에는
  필요 없는 완화다 (IMPORT.md §12). 필요해지면 그때 근거와 함께 넣는다
- `unsafe-eval` — 아래 참조
- 바깥 report endpoint — 그 자체가 바깥 전송이다

### `eval`은 빌드에서 지운다

`@pkmn/sim`의 `sim/battle-stream.mjs`가 `eval(message)`를 부른다. 그 경로는
입력 줄이 `>eval …`로 시작할 때만 도는 **Showdown 서버 콘솔의 디버그 명령**이고
우리는 그런 줄을 안 보낸다. 그래도 남겨 두지 않는다 — 코드에 `eval(`이 있다는
것만으로 `'unsafe-eval'`이 필요하다는 압력이 생기고, 디버그 기능 하나 때문에
페이지 전체의 스크립트 정책을 여는 것은 맞바꿈이 안 맞는다.

`pkmnDiet` 플러그인이 그 호출만 던지는 문장으로 바꾼다 (§4). 배포물 전체에
`eval(`이 **0건**이고, 매 빌드 `boundary:post`가 그것을 다시 잰다 — 다음에
다른 의존성이 들여오면 그때 걸린다.

### 그 밖의 헤더

| 헤더 | 값 |
|---|---|
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `no-referrer` |
| `Strict-Transport-Security` | `max-age=31536000` (https일 때) |
| `Cross-Origin-Opener-Policy` | `same-origin` |

`Cross-Origin-Embedder-Policy`는 **안 켠다.** `SharedArrayBuffer`를 안 쓰고,
켜면 blob:/data: 로딩 규칙이 까다로워져 OPFS 경로가 흔들린다. 필요해지는
날 다시 본다.

### 호스트는 아직 안 정했다

Vercel·Cloudflare·Netlify 중 무엇을 쓸지 정해진 바 없으므로 이 저장소에
그중 하나의 설정 파일을 넣지 않는다. **조건은 하나다: 위 응답 헤더를 실제로
붙일 수 있어야 하고, SPA fallback이 돌아야 한다.**

주소가 생기면:

```
pnpm verify:deploy https://<주소>/
```

그 검사를 통과한 적이 없으면 blocker 2번은 그대로다. **통과로 위장하지 않는다.**

## 4. 번들 출처 — 게임 데이터 0

`pnpm build`가 `.audit/bundle-provenance.json`을 남기고 `pnpm provenance`가
사람이 읽게 찍는다. `dist/`에는 안 넣는다 — 배포물이 아니라 감사 기록이고,
모듈 경로에 개발 기계의 절대 경로가 들어간다.

### 실측 (2026-08-11)

`dist/assets/battle-sim-*.js` = **483kB** (gzip 118kB). 6,547kB → 1,507kB → 483kB.

| 갈래 | minify 전 |
|---|---:|
| `@pkmn/sim` 정적 게임 데이터 | **0바이트 · 0개 모듈** |
| 엔진 코드 | 488kB |
| 우리 4세대 구현 (`src/engine/battle/dex/vendor`) | 388kB |

### 왜 이런 문제가 있었나

`@pkmn/sim`은 MIT다. 그러나 **패키지의 라이선스와 그 패키지에 담긴 게임
데이터를 우리가 배포할 권리는 다른 질문이다.** 종족값·기술 위력은 Pokémon
Showdown이 원작에서 정리해 넣은 표고, MIT가 그것에 대한 권리를 자동으로
해결해 주지 않는다.

⚠️ **오픈소스 라이선스가 Pokémon 데이터에 대한 권리를 준다고 주장하지 않는다.**
`@pkmn/sim`의 MIT 고지는 그 코드를 쓰는 우리의 의무고, 그것과 데이터 배포
권리는 서로 다른 층이다.

### 어떻게 갈랐나

**트리 셰이킹으로는 안 되는 자리였다.** `sim/dex.mjs`가 데이터 모듈 110개를
전부 **정적으로** import 해서 `dexData` 하나로 스프레드한다 — 참조가 살아
있으니 롤업이 뺄 수가 없다. 그래서 빌드에서 **모듈을 갈아 끼운다**
([`tools/distribution/pkmnDiet.mjs`](../tools/distribution/pkmnDiet.mjs)).

`data/` 아래 모듈은 이제 **하나도 안 남는다.** 세 갈래로 처리했다:

| 갈래 | 뺀 양 | 어디로 갔나 |
|---|---:|---|
| 안 쓰는 표 (습득기술·설명문·티어·별명·GO·다른 세대 모드) | 7,149kB | 없앴다. 팀 합법성 검사기만 보는 것들이다 |
| **수치·이름** (종족값·타입·특성·위력·명중률·PP·우선도·키·몸무게·상성·성격) | 1,344kB | **사용자의 롬**. `src/engine/battle/dex/provider.ts` |
| **효과 구현** (`onHit`·`secondary`·`condition`·룰·진행 스크립트) | 388kB | 우리 소스. `src/engine/battle/dex/vendor/*.gen.ts` (MIT, 원문 그대로) |

`tools/distribution/mechanics/bake.mjs`가 그 가르기를 한다. `Dex.forGen(4)`의
표를 **미리 평탄화하고**(gen5~8 사슬이 통째로 필요 없어진다) 항목마다 롬이
가진 칸을 빼고 남은 것만 소스로 굽는다. 콜백은
`Function.prototype.toString()`으로 **한 글자도 안 고치고** 옮긴다 — 자유
식별자가 하나도 없다는 것을 먼저 쟀다.

### 롬이 실제로 그 수치를 갖고 있는가 — 실측

### 이름표 다리

Showdown의 구현 코드는 서로를 **글자로** 부른다 — `pokemon.hasAbility('sturdy')`,
`move.type === 'Fire'`. 그래서 롬 번호와 그 id를 잇는 표가 필요하다.
**디컴프의 열거형에서 굽는다**(`raw/decomp/generated/*.txt`) — 패키지의 표를
베끼지 않는다는 뜻이고, `itemTable`·`spriteTable`과 같은 자리다.
`src/engine/battle/dex/vendor/names.gen.ts`가 그것이고 수치는 하나도 안 담는다.

⚠️ **디컴프 슬러그를 그대로 쓰면 안 된다.** `MOVE_HI_JUMP_KICK`은 `hijumpkick`인데
구현이 사는 자리는 `highjumpkick`이다(`faintattack`/`feintattack`,
`vicegrip`/`visegrip`도 같다). sim은 별명표로 찾아 주지만 우리 구현 표는 키로
직접 찾으므로, 슬러그를 그대로 쓰면 그 셋이 **조용히 구현을 잃는다.** 그래서
굽는 쪽이 찾은 항목의 `id`를 쓴다.

### 무엇이 이것을 지키나

|---|---|

⚠️ **오라클과 실행이 갈린다.** vitest는 `node_modules`를 SSR 외부화라 우리

따로 둔다 (`vitest.shimmed.config.ts`).

### 성별도 같이 고쳤다

개체를 sim에 넣을 때 성별을 **글자로 박아** 넘긴다. 비워 두면 sim이 성비로
자기가 굴리는데, 우리 개체의 성별은 이미 PID로 정해져 있다
(`(pid & 0xff) < 성비`). 둘이 따로 굴리면 화면에 ♀로 뜨는 애가 배틀 안에서는
♂가 되고 매혹·헤롱헤롱·투쟁심이 반대로 돈다.

⚠️ 그 대신 **난수 흐름이 밀렸다.** 씨앗을 못 박아 둔 시험 셋의 실측값이 같이
옮겨졌다 (`brain` 15·34 → 18·32, `controller`의 씨앗 13 → 14,
`protocol`의 관측 목록에서 `-ohko` 빠짐). AI가 나빠진 것이 아니라 같은 씨앗이
다른 판이 된 것이다.

### 그리고 `eval(`을 지웠다

`sim/battle-stream.mjs`의 `>eval <js>`는 Showdown 서버 콘솔의 디버그 명령이다.
우리는 그 줄을 한 번도 안 보내는데, **코드에 `eval(`이 있다는 것만으로**
CSP에 `'unsafe-eval'`이 필요해진다. 같은 플러그인이 그 호출만 던지는 문장으로
바꾼다. 지금 배포물 전체에 `eval(`이 **0건**이고, 그것을 `check.mjs`가 매
빌드 다시 잰다.

### 개발 서버도 같다

`optimizeDeps`는 롤업이 아니라 esbuild가 하고 그 길에는 위 플러그인의
`resolveId`가 안 불린다. 안 걸면 **개발판만 진짜 표를 들고 돌게 되고**, 표가
없어서 나는 문제를 배포 직전에야 만난다. 같은 규칙을 같은 파일에서 읽어
양쪽에 건다.

| `engine/battle/sim/bridge.ts` | `Dex` (`@pkmn/sim`) |

### 무엇을 안 재는지도 적어 둔다

- **⑤~⑧·⑱~㉒는 설치 기록을 손으로 심는다.** 재는 것은 부팅 갈래와 요청이지
  변환 정확도가 아니다 — 정확도는 ⑨가 노드 산출물과 바이트로 견준다. 진짜
  입력으로 끝까지 설치하는 것은 ⑮가 따로 잰다
- **⑫⑬⑭는 개발 서버다.** 공개 빌드에서는 타이틀 화면에 못 닿는다. 리포트
  왕복과 힙 측정은 배포 경계가 아니라 앱 동작이라 그쪽에서 잰다
- **④의 서버는 우리가 띄운 것이다.** 정본 CSP 아래에서 앱이 도는 것은

  어디까지 갔는지 못 가른다 — 읽기 전용 진행 표식을 내기 전에는 재는 척하지
  않는다

### 브라우저가 잡은 것

노드 시험으로는 못 닿던 버그를 이 하네스가 다섯 잡았다. ㉕는 그 위에 하나를
더 가르쳤다 — **화면에 글이 떴다는 것이 그 일이 끝났다는 뜻은 아니다.** 리포트
화면은 열리자마자 요약창에 주인공 이름을 띄우므로, 그 이름을 "다 썼다"로 읽고
나가면 쓰는 중에 화면을 떠난다. 끝난 자리에서만 뜨는 표식을 기다려야 한다.

| 무엇 | 어떻게 보였나 |
|---|---|
| 취소 버튼이 켜지자마자 누르면 안 먹는다 | `runInstall`의 설치 준비 구간에는 Worker에 걸린 일이 없어 `cancel()`이 no-op였다. 이제 `runInstall`·Worker 메시지·2초 뒤 `terminate()` 세 군데에 건다 |
| 96MB 파일 하나에 힙이 두 번 두 배 | 되읽기 +126MB → **+31MB**, 해시 +97MB → **+0MB** |
| 영어 롬으로 설치하면 오버월드가 통째로 죽는다 | `worldData`와 공중날기 화면이 지역 이름 파일을 **로케일 `ko`로 박아** 읽고 있었다. 개발 서버에는 세 벌이 다 있어서 안 걸렸고, 진짜 설치본에는 고른 롬의 언어 하나뿐이라 `/play`가 빈 화면이 됐다 — DOM이 없어서 "무엇이 없다"조차 안 보였다. ㉕가 잡았다 |
| 한 그룹이 죽으면 스물셋이 통째로 없던 일이 된다 | `runInstall`이 첫 실패에서 그대로 던졌다. 무대 하나가 깨진 폴더를 고르면 Platinum 스물두 그룹이 다 날아가고 예외 문구 하나만 남았다. 이제 죽은 그룹은 이름과 이유로 적히고 나머지는 끝까지 간다 — 취소와 저장 공간만 예외다 |
| 화면만 떠도 변환기 스레드가 생긴다 | `ImportWizard`가 마운트하면서 Worker를 띄웠다. 하다 만 설치본으로 다시 접속하면 사용자가 아무것도 안 눌러도 스레드가 하나 생긴다 — ⑰이 잡았다. 이제 필요할 때 만든다 |

⑭가 `+0.5배`를 넘으면 실패한다. 옛 코드로 되돌려 실제로 걸리는 것을 확인했다.

## 6. 공개 전 점검

```
pnpm check                    타입 · lint · 시험 (자료 있는 기계)
pnpm build                    경계 앞뒤 검사 포함
pnpm e2e                      브라우저 실측 (§5)
pnpm provenance               번들에 무엇이 들어갔는가
pnpm release:check            blocker가 하나라도 있으면 실패
pnpm verify:deploy <url>      실제 호스트의 CSP · 외부 요청 · SPA fallback
```

첫 공개 remote를 만들기 **전에** 해야 하는 것이 하나 더 있다: Git 히스토리에서
원본 유래 산출물을 지우는 것. 파괴적 작업이라 사용자 승인이 따로 필요하다 —
대상 목록·백업·실행·검증·force-push 절차는 [`HISTORY.md`](HISTORY.md).

신고를 받으면 무엇을 어떤 순서로 하는지는 [`TAKEDOWN.md`](TAKEDOWN.md)에 미리
정해 뒀다. 상황이 생긴 뒤에 정하면 늦다.
