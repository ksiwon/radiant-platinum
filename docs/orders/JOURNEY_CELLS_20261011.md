# 게임 전체 판을 열여섯 칸으로 — 설계서

사용자 결정은 세 번에 걸쳐 나왔다.
- **10-08:** 여섯 파트로 쪼갰다(`JOURNEY_PARTS_20261008.md`).
- **10-10:** 「P를 좀 더 잘게 쪼갤 필요는 없겠나」 → 「배포 끝내면 그렇게 하자」.
- **10-11:** 「`_dw`, `_league` 안 쓰고 전부 journey 통일」 → 이 16칸 설계 승인. 「하네스가 수정되었다고 해서, 이전껄 다시 돌릴 필요는 없어」.

10-10에 판이 하네스 문제로 선 것이 일곱 번이다. 하나 고칠 때마다 파트를 처음부터 돌아 1~2.5시간씩 잃었다. 칸 하나를 20~60분으로 줄이고, **실패하면 그 칸만 바로 앞 칸의 끝 세이브부터** 다시 돈다.

이 문서는 `JOURNEY_PARTS_20261008.md`의 §1(파트 표) · §5(탐침을 파트로) · §7(명령)을 대신한다. 나머지 원칙(§2 잇는 규칙 · §3 세이브 밖 상태 · §4 줄 나누기)은 칸에 그대로 옮긴다.

## 1. 칸 표

모든 칸은 **`tools/e2e/journey.mjs` 하나**가 돈다(`--cell=N`). `_dw.mjs` · `_league.mjs`는 칸 판에 안 쓴다 — 그 다리의 걸음(`badgesDW.mjs` · `badgesLeague.mjs`)만 journey가 부른다.

**배지 칸의 경계:** 관장을 이긴 뒤 그 마을 센터에서 낫고 나온 자리다. 기믹 체육관(들판 물 · 선단 얼음)은 들어갈 때의 풀이를 문을 목표로 한 번 더 돌린 뒤 나간다(지금 코드 그대로).

- 칸 13(다리 j)은 시작할 때 80 · 78 · 78.

## 2. 잇는 규칙

1. **시작 세이브는 앞 칸이 통과하며 남긴 끝 세이브뿐이다** (`.audit/parts/cell-(N-1).rpsave` + 옆의 하네스 기억 `.memory.json`). `--save`로 다른 것을 주면 그 판은 **진단**이다.
2. 칸마다 봉투 하나를 쓴다(`.audit/parts/cell-N.json`). 담는 것은 다음과 같다.
   - 시작 세이브 · 끝 세이브 다이제스트
   - source · data · **harness** 다이제스트
   - 결과 줄 · 걸린 시간
3. **최종 판정은 연쇄 통과다** (`pnpm parts:check`). 다음을 모두 만족해야 한다.
   - ① 16칸 모두 PASS이고 기대한 줄을 다 냈다.
   - ② 칸 N의 시작 세이브 다이제스트 = 칸 N-1의 끝 세이브 다이제스트.
   - ③ **source · data 다이제스트가 16칸 모두 같다.**
   - ④ harness 다이제스트는 칸마다 **적기만 한다.** 하네스는 게임 상태를 안 바꾸므로 하네스만 고친 것은 연쇄를 끊지 않는다 (사용자 10-11 「하네스가 수정되었다고 해서, 이전껄 다시 돌릴 필요는 없어」 · 10-08 §2.5와 같다).
   - ⑤ 칸 1은 새 게임에서 시작했다.
4. **하네스를 고치면** 막힌 칸부터 바로 다시 돈다(`pnpm parts --from=N`). 앞 칸은 다시 안 돈다 — 그 칸의 끝 세이브가 그대로 시작 세이브다.
5. **src나 data가 바뀌면** 연쇄가 끊긴다. 최종 판정은 칸 1부터 다시다.
   - 판 도중 src 금지.
   - 다이제스트 규칙은 [[건너뛰기는 다이제스트로 잠근다]]를 따른다.
6. 판은 한 번에 하나다. 개발 서버는 `pnpm parts`가 **하나 띄워 모든 칸이 같이 쓴다**(`--url`). 칸마다 3~4분, 붐비는 날 5~10분이던 기동을 한 번만 치른다.

## 3. 세이브 밖 상태

10-08 §3의 표를 그대로 따른다. 칸이 잘게 나뉘면서 새로 걸리는 것은 하나다.

- **산 약 개수 `potionBuy`:** 같은 묶음 한가운데(32 · 35 · 45)에서 시작하는 칸은 앞 구간이 산 기록이 없다.
  - 그래서 칸을 시작할 때 **가방의 좋은상처약 개수에서** 읽는다.
  - 한 판으로 이어 돌 때와 같은 몫을 쓰게 된다.

장애물 기억 · 파도타기 · 락클라임 모드는 이미 하네스 기억(`harnessMemory`)으로 칸 사이를 건넌다.

## 4. 명령

| 명령 | 하는 일 |
|---|---|
| `pnpm part <N>` | 칸 하나. 시작은 앞 칸 끝 세이브. 로그는 `.audit/parts/cell-N-<커밋>.log`(tee) |
| `pnpm part <N> --save=<file>` | 진단 |
| `pnpm parts` | 칸 1→16. 못 닿은 칸에서 멈춘다 |
| `pnpm parts --from=N` | 칸 N부터 이어 간다(앞 칸 봉투가 그대로 쓰인다) |
| `pnpm parts:check` | 16 봉투로 연쇄 조건만 판정 · `.audit/parts.html` |

## 5. 예산

10-08 실측(새 게임 한 판 `965c569`)을 기준으로 잡는다.
- 새 게임 → 배지 2: 70분
- → 배지 5 직전: 90분

탐침 판들 기준은 다리 e~i가 2시간 안팎, j~m이 2시간 안팎이다. 칸 예산은 실측의 두 배로 둔다.

| 칸 | 예산 |
|---|---|
| 1 · 2 | 60분씩 |
| 3~7 | 60분씩 |
| 8~16 | 45분씩 |
| 11 · 16 | 90분씩 (깨어진 세계 · 사천왕은 김) |

첫 연쇄를 재고 고친다.

## 6. 옛 파트 봉투

`.audit/parts/part-1~5.*`는 옛 소스(`374528071596`)의 파트 판이다. `.audit/parts/keep-6parts-20261011/`에 복사해 두었고(원본도 그대로), 칸 판은 `cell-*` 이름을 쓴다 — 서로 덮지 않는다.
