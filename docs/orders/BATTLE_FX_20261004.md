# 트레일러를 보고 어색한 여섯 — 계획 (2026-10-04)

사용자가 트레일러 첫 판(`.audit/reels/out/radiant-reveal.mp4`)을 보고 짚은 여섯이다. 넷은 게임을 고치고, 둘은 찍는 쪽을 고친다.

## 사용자 결정

- **배틀에 사람이 안 선다 — 양쪽 다.** 주인공 · 동행 · 상대 트레이너 모두. 볼이 화면 밖에서 튀어나와 포켓몬이 차례로 선다.
  진 트레이너가 다시 걸어 들어오는 연출과 포획 튜토리얼의 동행 모습도 같이 빠진다. 「내가 꼬링크와 싸우는 것 같다」가 이유다.
- **포획 · 내보내기 · 기술 이펙트는 BDSP 것을 옮긴다.** 손으로 만든 도형을 다듬는 길이 아니라 원작 파티클을 three.js에서 그대로 튼다.

## 1. 연표의 「디아루가·펄」 — 끝

4세대 첫 줄은 「다이아몬드·펄」이다 (`tools/reels/cards.mjs` `LINEUP`).

## 2. 나무열매 나무가 평면 그림이다

**원인** — 플래티넘은 나무를 성장 단계별 스프라이트로 그리고, 우리는 그걸 카메라를 보는 판으로 세웠다(`scene/BerryPatchProps`).
흙만 3D(`fldeff.narc` 17)다.

**BDSP에 나무가 있다** — `Environments/gimmick/kino001`~`kino065`가 열매마다 한 벌이다(65번은 BDSP가 더한 열매).
한 벌이 `Miki`(줄기 · 잎) · `Hana`(꽃) · `Mi`(열매) 세 묶음이고, 싹은 `kinoseeding`, 젖은 흙 · 돋운 흙은 `kinowet` · `kinomori`다.
메시는 `MeshFilter` 정적 메시라 무대 굽는 쪽(`bdspArena.py`)으로 굽는다.

**할 것**
- 굽는 쪽 둘 다 — `tools/extract/bdspArena.py --berries`와 브라우저 변환기. 묶음마다 노드를 따로 두어 실행 쪽이 단계에 맞게 켠다.
- 단계 ↔ 묶음: 싹 = `kinoseeding` · 자람 = `Miki` · 꽃 = `Hana` · 열매 = `Mi`. 심은 직후(빈 흙)는 지금처럼 흙만.
- 설치 필수 목록 · e2e 픽스처 · 자료 판(`assetFormat`)을 같이 올린다.

## 3. 배틀에 사람이 선다

**지금** — `scene/battle/BattleTrainers`가 주인공(늘) · 동행 · 상대 트레이너를 BDSP 몸으로 세우고, 첫 볼을 그 손에서 던진다
(`battleBallMotion.trainerStandAt`). 카메라는 `ballOpen.p1a`까지 트레이너를 잡는다(`BattleStage` `useBattleCamera`).

**할 것**
- `BattleTrainers`를 무대에서 내린다. 첫 볼도 화면 밖(`trainerThrowOrigin`)에서 온다.
- 카메라가 트레이너를 기다리지 않는다. 내보내는 차례(상대 → 나, PARITY §2.28)와 박자(`playback` `HOLD_*`)는 그대로.
- 야생은 지금처럼 볼 없이 서 있다.
- 트레이너 몸에 묶인 단위 시험을 정리한다(`battleBallMotion.test` 50~134행 · `battleTrainerVisual.test`).

## 4. 포획 · 기술 이펙트가 싸 보인다

**지금** — 포획은 노란 반투명 구 + 팔각 구슬(`BattleBallEffects` `Flash`), 기술은 DS `.spa` 파티클 + 다섯 가지 도형(`MoveVfx`).

**BDSP에 원본이 있다** — `Effects/effect/prefab/battle`에 2,034벌:

| 머리 | 수 | 무엇 |
|---|---|---|
| `eb###_capture` · `eb###_ballout` | 53 | 볼마다 포획 · 내보내기 |
| `ew###_…` | 1,724 | 기술 (번호 = 기술 번호) |
| `ee` · `ef` · `es` · `eg` · `et` · `cmn` | 257 | 상태 · 날씨 · 공용 |

한 벌이 Unity 파티클 시스템(Shuriken) 여럿이다 — `eb001_capture`가 파티클 13 · 힘장 2.

**잰 것** (2,034벌 · 파티클 시스템 15,389개 · 시퀀스 1,235개 — 스크래치 `bdspfx/`)
- 모듈: 크기 · 회전 · 그림 칸 · 속도 · 힘 · 속도 제한(감쇠로만 씀) · **CustomData(86% — 셰이더가 색 둘을 여기서 받는다)**.
  모양은 구 · 원 · 원뿔 · 모서리 · 상자 · 사각형이 99.7%. 렌더러는 판 · 늘인 판 · 메시 · 수평 · 수직.
- 셰이더는 `FxSystem/Particle` 하나다(Switch 전용 블롭이라 소스는 없다 — 속성 77개 · 키워드 118개가 명세다).
  90%가 특수 기능 없이 「텍스처 셋 채널 고르기 · 곱/더하기 · 색 두 개 보간 · 정점색 곱」이다. 섞기는 알파 67% · 더하기 31%.
- 기술 → 시퀀스: `BattleDataTable.BattleWazaData`의 `CmdSeqName`(= `ew###`). 시퀀스는 30fps 명령 시간표다
  (`ParticleCreate` · `ParticleMoveRelativePoke` · `PokemonAttackMotion` · `CameraMoveRelativePoke` …).
- 볼: `BallEffectData` — 볼 번호 n = `eb00n_capture` · `eb00n_ballout`. 포획 흐름은 `ee101`(던지기 · 빨아들이기) ·
  `ee102~104`(흔들기) · `ee105`(성공) · `ee106~109`(튀어나옴).

**짜임**
- **굽는 쪽은 하나** — `src/import/bdsp/fx.ts`(브라우저 변환기). 개발용 `public/data/fx/`도 노드에서 같은 코드로 굽는다
  (`tools/extract/bdspFx.mjs`). 두 굽는 쪽이 갈릴 자리가 없다. 프리팹 JSON · 그림 PNG · 시퀀스 JSON · 표(볼 · 기술 → 이름).
- **좌표는 유니티 그대로 굽고** 실행 쪽이 X를 뒤집는다(다른 BDSP 모델과 같은 손잡이).
- **실행 쪽** `src/scene/battle/fx/` — 파티클 시스템 CPU 시뮬레이션 → 인스턴스 사각형 · 메시. 재질은 TSL 노드 하나로
  셰이더 키워드를 유니폼으로 받는다. 시퀀서가 30fps로 명령을 튼다. 시험대 `/fxlab`에서 프리팹 하나씩 찍어 본다.
- **차례**: 포획 · 내보내기(볼 16종) → 기술 467개. 프리팹이 없는 기술은 지금의 DS 입자가 선다.

## 5. 깨어진 세계에서 허공에 섰다 — 찍는 쪽

확인 지점 `distortion`은 빈 칸이 가장 많은 자리를 고르는데(`checkpoints.openSpot`), 1층에서 그 자리가 허공 가장자리였다.
트레일러는 이야기가 실제로 내려놓는 칸(롬 (55,40) → 1층 로컬 (34,30)의 서쪽 한 칸)에 세운다 (`takes.mjs` `E3-distortion`).

## 6. 기라티나 배틀 배경이 풀숲이다 — 찍는 쪽 + 게임

**찍는 쪽** — 배경은 배틀이 설 때의 `world.mapId`로 한 번 정해진다(`BattleStage` `arenaFor`). 트레일러가 582에 내려앉기 전에
배틀을 열어 시작 맵의 풀숲이 박혔다. 맵을 기다리게 고쳤다 (`capture.mjs` `map` 단계).

**게임** — 내려앉은 뒤에도 배경은 깨어진 세계가 아니라 **창기둥**이다. BDSP에 깨어진 세계 무대가 없어서 `槍の柱2`(g069)를
빌렸다(`arena.ts` 17번). 깨어진 세계 무대를 따로 세운다 — 붉은 바위 발판 · 푸른 허공 하늘 · 떠 있는 바위.

## 7. 트레일러 다시 찍기

2~6이 들어가면 배틀 장면(C1 · C3 · C6 · C9 · D9 · D11 · E1 · E3)과 꽃밭(B4 · D3)을 다시 찍는다.
