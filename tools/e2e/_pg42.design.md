# _pg42 새 케이스 설계 (시원 사슬 · 전설 사슬 · 배틀존 · 팩토리)

판정이 아니라 **진단 탐침**이다. 제품 코드(src/ public/)는 안 고친다. 읽는 값은 제품이 export하는 것만 —
`fieldScripts.vars` · `useSaveStore` · `useBattleStore` · `useFactoryStore` · `useHatchStore` · `npcActors` · `world` ·
`document.documentElement.dataset`. 못 읽는 것은 `관측 불가`로 적고 null/false로 접지 않는다.

## 공통 규칙

- **통과는 같은 케이스를 2번 연속(`--repeat=2` 기본) 통과해야** PASS로 적는다. 다크라이는 3번(`--repeat=3`).
- 기다림은 고정 `waitForTimeout`이 아니라 `until(조건, 상한)` 폴링이다. 고정 대기는 키 사이 간격에만 쓴다.
- 서면(`halt`) 한 줄: 맵 · 칸 · 씬 · 대사 · 도는 스크립트 · 스크린샷 경로.
- 계측 검증: 가방/파티/변수는 **바뀌기 전 값을 먼저 읽고 바뀐 뒤 값을 읽어** 읽기가 상태를 따라가는지 본다
  (선물 전 0 → 후 1, 변수 0 → 마법의 수). 대사는 제품의 `siwonLines()`와 **화면 글(innerText)을 맞대어** 어떤 대사인지 가린다.
- 변수 번호는 `raw/decomp/generated/vars_flags.txt`에서 세어 냈고(플래그는 `commands.ts`의 2404 · 시원의 344/291/286과 맞음,
  변수는 0x4000 + 순번 — 16471/16542/16664가 기준) 아래 표의 수가 그것이다.

## 케이스별 설계

### siwon
(a) 원작/우리 규칙: SIWON.md §5 표, `world/siwon.ts` `siwonTurn` — 전당등록 전 locked, 앞 선물의 `used` 신호가 서야 다음.
(b) **지름길**: 「썼다」 신호만 개발 모듈로 — 로토무 폼(박스에 로토무 form1 한 마리) · `FLAG_CAUGHT_DARKRAI` · `FLAG_CAUGHT_SHAYMIN` ·
유적 상태 변수 16489=290. 파티 한 마리만 남기기(자리 확보). 나머지는 시원 앞에서 키(↑ 한 번 + Space)로 말을 건다.
(c) 읽기: `siwonGiven` · 가방 도구 수(전 주머니 합) · 파티(종 · 레벨 · 알 · 운명적 만남 · 친밀도) · 배포 변수(VM) · 대사 분류.
(d) 판정: 단계마다 `given` +1, 해당 도구/마리 +1, 배포 변수가 마법의 수, 대사가 `gift[n]`.
(e) 음성 대조: ① 전당등록 전 locked(아무것도 안 변함) ② 파티 6일 때 partyFull(`given` 0) ③ 신호 전 wait[n](`given` 그대로, 다음 도구 0, 배포 변수 0)
④ 일곱 뒤 done(스냅샷 동일).
